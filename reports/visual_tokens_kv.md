# 视觉 token → KV cache 显存分析

模型 Qwen2.5-VL-3B · layers=36 · kv_heads=2 · head_dim=128 · dtype=bf16

## 全量 624 张的视觉 token 分布（processor 实测，纯 CPU）

| 配置 | 视觉 token 最小值 | 最大值 | 均值 | 中位 | >1 万 token 张数 |
|---|---|---|---|---|---|
| 无约束（默认 12.8M） | 373 | 16307 | 3623 | 1821 | **84 张** |
| `longest_edge=2M` 约束 | 373 | 2669 | 1776 | 1821 | 0 张 |

- 无约束时 **84 张**大图（面积 ≥ A4，占全部 624 张的 13.5%）切成 >1 万视觉 token，
  最高 **16307**；2M 约束后全部压到 **≤2669**，视觉 token 总量 **削减 51%**（226 万 → 111 万）。
- 大图才是视觉 token 爆炸的源头：小票（中位 1821）几乎不受约束影响，大图被约束显著压低。

## 单序列 KV cache 对比

| 场景 | 视觉 token | 总序列长度 | KV cache |
|---|---|---|---|
| 纯文本（无图） | 0 | 200 | 7.0 MB |
| VLM + 500 视觉 token | 500 | 700 | 24.6 MB |
| VLM + 2645 视觉 token | 2645 | 2845 | 100.0 MB |
| VLM + 11000 视觉 token | 11000 | 11200 | 393.8 MB |

## 结论

- 纯文本 200 token 的 KV cache 仅 **7.0 MB**；
- 大扫描件 ~11000 视觉 token 时 KV cache 达 **393.8 MB**（是纯文本的 **56 倍**）。
- 这解释了 W2 实测：大扫描件未约束时峰值显存 21GB（30 样本 diag，bnb4 未约束）、
  延迟 60s+（bf16 全量 624 张中 13 个大图样本）——KV cache 随
  视觉 token 线性爆炸，但 21GB 峰值里 KV cache 只占零头（394MB），大头是视觉塔中间
  激活 + attention 矩阵，两者共同构成 VLM 边缘部署的第一显存瓶颈。
- `longest_edge=2M` 约束的**全量收益**：视觉 token 总量削减 51%，大图峰值 token 从
  16307 → 2669（−84%），配合 bnb4 把峰值显存从 21GB 压回 3.7GB 舒适区。
- 优化方向（W3）：① 视觉前缀缓存（跨请求共享视觉 K/V）；② 分辨率约束（longest_edge）；③ KV 量化（fp8/int4）；④ PagedAttention（碎片化）。
