## 4. 为什么能离线：`resolve_model`

逻辑（`src/utils/model_download.py`）：

1. 模型名是本地路径 → 直接用；
2. 项目根下有同名目录 → 用；
3. 找 ModelScope 缓存：`<cache_dir>/models/<org>--<model>/snapshots/<revision>`；
4. 都没有才 `snapshot_download`；
5. 失败回退 HuggingFace id。

**一句话表述**：
> “模型按 ModelScope 缓存布局自动解析，演示环境完全不依赖网络；现场断网也能起服务。”

**验证离线（可选）**：

```bat
set HTTP_PROXY=http://127.0.0.1:9
set HTTPS_PROXY=http://127.0.0.1:9
set ALL_PROXY=http://127.0.0.1:9
```

再启动服务。能起来 = 没联网。

## 6. 常见故障速查

| 症状 | 原因 | 解决 |
|---|---|---|
| `python` 报 `No module named ...` | 用了 3.12 | 改用 `py -3.11` |
| `No module named src` | 不在项目根 | 先 `cd /d` 到项目根 |
| `Errno 10048` | 8000 被占 | `netstat` + `taskkill`；或直接用已有服务 |
| “服务就绪”但没有 Uvicorn running | 绑定失败 | `curl /health` 验证 |
| OOM | 与 SciTriple 同时驻留 | 先跑 SciTriple（进程退出释放），再起 VLM |
| curl 连不上 | 服务没起成功 | 回服务终端看最后一行；`/health` |
| 字段大小写/标点与金标不同 | 正常 | 讲 exact vs normalized |
| 图片 404 | 不在项目根/路径错 | 用相对路径 `data/raw/sroie/img/...` |

## 7. 现场 7 分钟展示剧本（项目二）

> 适用：评审说“讲一下第二个项目”或“现场跑一下”。
> 结构：**定位 40 秒 → 量化 90 秒 → 视觉 token 60 秒 → 系统 90 秒 → live 60 秒 → 精度/跨域 40 秒 → 收束 20 秒。**

### 0:00–0:40 定位

> “项目二是图片侧：SROIE 收据，抽 company / date / address / total 四个字段。
>
> **我没有微调，是零样本**——因为我的重点不是再训一个模型，而是回答‘一个 3B 多模态模型能不能在 8GB 边缘设备上跑得动、跑得快、扛得住并发’。”

> 主动说“没微调”，避免被追问“是不是调包”时被动。

### 0:40–2:10 量化（打开 `quant_summary.md` + `quant_pareto.png`）

> “全量 624 张，bf16 vs bnb4：
>
> exact 0.8451 → 0.8304；normalized 0.9501 → 0.9330；延迟均值 19.6s → 7.1s；中位 17.1s → 6.0s；峰值显存 7799MB → 3710MB；权重 6132MB → 2302MB。
>
> 结论：精度只掉 1.7 个点，中位延迟快 2.85 倍，峰值显存降 52%。这是同一批图、同一 prompt、同一台机器测的 Pareto，不是引用别人的数字。”

### 2:10–3:10 视觉 token（打开 `visual_tokens_kv.md`）

> “Qwen2.5-VL 是动态分辨率，图越大 token 越多。原始数据有 84 张图超过 1 万视觉 token，最大 16307；不限制时显存 15.97GB 直接 OOM。我把 longest_edge 限制到 2M 像素，单图上限降到 2669，总量削减 51%，KV cache 从 21GB 降到 3.7GB。
>
> 这是质量-成本权衡：限制分辨率会损失小字，但换来了 8GB 卡能跑。”

### 3:10–4:10 系统（打开 `w3_batching.md` / `w3_kvquant.md` / `w3_prefix_cache.md` / `w4_serving.md`）

> “批处理 batch 1/2/4：吞吐 0.178 / 0.228 / 0.247 张/秒，单张延迟 5.63 → 4.04 秒，峰值显存 3670 / 4968 / 7591MB。吞吐不是线性涨，因为单卡算力和带宽是瓶颈；batch 4 已接近 8GB 上限。
>
> KV 量化：int8 基本无损，int4 直接崩——KV 里有 outlier，4bit 太粗。
>
> 前缀缓存：我测了，R≈0。因为每张图都不同，system prompt 又很短，没有可复用前缀。**负结果也是结果**，它告诉我这个场景不该把预算花在 prefix cache 上。
>
> 服务化：FastAPI + lifespan 全局单例，GPU 推理用锁串行化；并发 1/2/4：QPS 0.18 / 0.22 / 0.22，P95 5.9 / 9.1 / 18 秒。**并发只涨延迟、不涨吞吐**，说明单卡已打满。”

### 4:10–5:10 live curl

先 `/health`，再 curl 042：

```bat
curl http://127.0.0.1:8000/health
curl -X POST -F "file=@data/raw/sroie/img/042.jpg" http://127.0.0.1:8000/extract
```

> “现场这张图四个字段全对；exact 下大小写/标点算错，normalized 下算对。所以我的主指标是 normalized，exact 作为严格下界。”

### 5:10–6:10 精度定位（打开 `accuracy_positioning.md`）

> “SROIE 官方 SOTA 大约 0.95，但那是训练过 + OCR 先验的序列标注；我是零样本 3B 4bit 生成式，0.933 normalized 不能直接和它比。我能说的是：在这个约束下它已经是可用的上游水平；要再往上，需要微调或加 OCR 先验。”

### 6:10–7:00 跨域 + 收束（打开 `xfund_generalization.md`）

> “XFUND 中文表单 50 张零样本，字段级 normalized F1 0.4072（P 0.43 / R 0.39）。它证明模型懂通用‘字段→值’抽取，不是背 SROIE 四字段；但 0.4072 也说明跨语言、跨版式还远没到可用，这是局限。
>
> 所以这个项目的价值是：**把 3B 多模态在 8GB 边缘设备上的精度-延迟-显存代价测清楚了，并给出了可落地的配置。**”

## 8. 翻车兜底

| 情况 | 应对 |
|---|---|
| 没网 | 全程离线；直接说“不依赖网络”，照常起服务 |
